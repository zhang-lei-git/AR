# AR生产现场作业支撑平台演示系统

## 系统定位

本系统面向液压支架整架装配技术验证，以单架产品装配工单为主线，覆盖八个主要工序。管理端供工艺工程师、生产管理人员、远程专家和系统管理员使用；现场人员通过AR终端完成工单领取、作业内容查看、现场数据采集、智能问答、异常上报和远程协作。

系统采用浏览器应用、Python服务和SQLite数据库，可独立部署。AR终端、企业知识服务、远程协作服务和数字孪生平台均通过通用接口适配，不在演示系统中限定厂商或产品。

## 快速启动

要求 Python 3.10 或以上，无第三方运行依赖。

```bash
python3 server.py --host 127.0.0.1 --port 8088
```

管理端访问 `http://127.0.0.1:8088/`，AR终端模拟器访问 `http://127.0.0.1:8088/terminal.html`。企业知识服务参数保存在不下发浏览器的 `.env.local`。

## 云服务器部署

仓库提供 `deploy/systemd/ar-production-support-demo.service`，默认使用独立目录 `/opt/ar-production-support-demo`、独立数据文件 `/opt/ar-production-support-demo/data/ar_demo.db` 和端口 `5008`。生产部署时应将 `.env.example` 复制为仅服务账号可读的 `.env.local`，填写知识服务地址、API密钥和会话标识；不得将 `.env.local` 提交到版本库。

服务管理命令：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ar-production-support-demo.service
sudo systemctl status ar-production-support-demo.service
```

## 演示主线

1. 管理端创建单架液压支架装配工单，绑定工位、已发布工艺版本、八个主要工序和目标AR终端。
2. 工单下发后，AR终端在可移动、可缩放、可最小化的悬浮窗口中领取工单，管理端保持可操作。
3. 现场人员识别零部件编码，平台按照产品型号、装配工单、当前工序和BOM进行校验，返回匹配通过、人工复核或错误拦截结果。
4. 校验通过后采集现场照片并确认工序，识别记录和现场数据实时回传管理端；错误件不能用于完成当前工序。
5. 智能问答自动携带产品、工单、工艺版本和当前工序上下文，返回受控资料引用或明确拒答。
6. 现场上报异常后工单暂停，远程专家接入第一视角画面，完成冻屏标注、资料发送、处置建议和会话归档。
7. 异常关闭后继续执行剩余主要工序，最终形成整架完工状态和全过程追溯记录。
8. 智能维修辅助接收维修管理系统的设备档案和维修工单，检索知识库与历史案例，现场处置结果经审核后回写维修工单并形成知识案例。
9. 产线透视复用产线数字孪生平台的模型、工位对象、实时参数和告警，管理端完成对象配置，AR端查看产线三维模型和现场数据。

## 主要管理功能

- 工艺管理：支持工艺版本新建、编辑、发布、回退和主要工序维护，已发布版本可用于装配工单创建与下发。
- 知识资料管理：支持资料上传、分类、标签、查询、查看和下载，并展示RAG索引状态。
- 过程追溯：支持按工单、工序、设备、人员和关键字查询，统一展示事件时间轴与AR眼镜现场录像。
- AR终端模拟器：采用16:9显示比例，关键作业信息在一屏内呈现；悬浮窗口支持拖动、缩放、最小化，不影响管理端操作。

## 三维加载优化

管理端首页不加载Three.js，进入装配工单或打开AR终端时按需加载三维模块，并在加载期间显示结构件预览。静态HTML、CSS和JavaScript支持Gzip传输，脚本、样式、图片和视频采用七天浏览器缓存；三维渲染限制像素比为1.25、阴影贴图为1024，并在无交互时停止连续重绘。

## 正式项目扩展安排

本部署包真实实现工单创建与下发、AR端领取、零部件编码解析、型号与工单及工序和BOM校验、错误拦截、现场数据回传、工序状态、知识问答、异常处置、远程协作记录、维修案例、并行工单、SQLite持久化和追溯导出。产线数字孪生与维修管理系统采用样例接口和样例数据完成模型展示、实时数据关联、维修工单接收及结果回写流程。正式项目仍需按目标AR终端开放接口完成真机适配，并对接客户数字孪生平台、维修管理系统、零部件主数据和BOM正式接口。
